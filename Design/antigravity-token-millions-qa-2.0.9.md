# Antigravity Token 卡片调整 · 2.0.9

## 展示与统计约定（实现前）

- 问题：在紧凑菜单栏卡片内，统一比较包含缓存命中的本机已记录 Token 总量、模型分布与每日强度。
- 主指标：AG ModelUsageStats 输入 #2 ＋ 输出 #3 ＋ 缓存命中 #5；输出已含思考，不再次叠加 #9。仅明确合并缓存命中，不把缓存写入或原始厂商 API 的不同口径猜测加入。不是计费或账户全设备用量。
- 形式：总量 KPI、三列输入 / 输出 / 缓存明细、两列模型汇总；保留近 18 周 18 × 7 公历日期强度方格，不另增图表或滚动容器。
- 数值：总量、三项明细、模型与日期值均以 M（1,000,000 tokens）显示，统一两位小数，千位分组；非零小值低于 0.01 M 用 `<0.01 M`。不再混用 K、B 或每日原始整数。
- 数据充分性：已有 18 周日期网格，真实记录可稀疏；未知与部分状态继续为空心 / 虚线，不补猜测的零。无法归日的缓存仍计入总量，不按刷新时间或 mtime 分摊。
- 一致性：按同一去重后的模型 / 日期聚合把 cache_read 加一次；总量与模型汇总包含全部已读记录，日期格只包含可可靠归日的记录。历史缓存 v2 已有原始分项，不改 schema、不清空缓存、不新增源查询、定时器、网络或监听。
- 颜色与交互：保留现有 AppTheme 青色单色深浅及中性轨道，以虚线、未知文字和部分状态作非颜色区分。保留日期点击 / 悬停，仅读内存。
- 容器与验收：生产卡片所在面板宽 340 pt；使用现有原生 SwiftUI 视图。测试总量相等、缓存去重、旧缓存重算、零 / 未知 / 大小值，再检查中英文浅 / 深色和四模型原生 / 离线渲染。

## 口径依据与限制

本轮只读核对本机 Antigravity 2.12.2 的 ModelUsageStats 描述符，字段分别为 input_tokens、output_tokens、cache_read_tokens。现有本机缓存中存在缓存命中大于输入的记录，因此不能把 AG 的 input_tokens 直接当作含缓存的原生 Gemini promptTokenCount。本轮采用用户要求的 AG 已记录字段合计，而非推算厂商账单。

厂商原始口径并不统一：[Gemini UsageMetadata](https://ai.google.dev/api/generate-content#UsageMetadata) 与 [Claude prompt caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching) 仅作口径边界参考，不替代本机 AG 协议验证。内部协议可能变化，仍保留部分 / 不可用降级。
